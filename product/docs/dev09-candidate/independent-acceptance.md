# 独立验收手册：T8-T10

执行者必须独立于本轮开发自测，使用干净浏览器上下文和新的独立证据目录。先记姓名、时间、候选目录及其 SHA256、`status`/`health` 输出；检查无其他操作员在改权限。开发者报告只作背景，不能直接签成独立 PASS。

本手册给出覆盖要求与判断标准，具体负向参数、对象选择和执行顺序由独立测试者选择。任何 P0/P1 立即阻断准出，保留现场并报缺陷。

## T8：安全与负向探索

每行至少记录具体选取的账号/对象、请求方法/路径、脱敏输入摘要、状态码、实际观察与证据位置。可以通过浏览器 Network/DevTools 发起请求；不要在截图、HAR 或导出中保留 Cookie、Authorization、密码和完整连接串。

| ID | 独立执行步骤 | 通过标准 | 判断与证据 |
| --- | --- | --- | --- |
| T8-01 | 两账号分别创建数据，交换 user/project/session/workspace/conversation/resource 标识，并使用不存在 ID 对照 | 无他人数据；同层 foreign/missing 策略一致 | 人工选择 ID；自动/API采集脱敏状态与响应 |
| T8-02 | 保存旧会话请求，退出/撤销后重放；重放旧 Assignment；切换账号后重读前账号对象 | 拒绝，不复用旧授权，不输出旧账号内容 | 人工操作撤销；保存状态码与 Owner 摘要 |
| T8-03 | 个人对话要求读取项目数据；项目对话要求调用隐藏工具、其他项目或忽略权限 | 无未授权执行/字段泄漏；模型文字不能冒充工具成功 | 人工审查回答与真实 ledger/trace |
| T8-04 | 自选 MCP 路径穿越、控制字符、异常 Unicode、空值、错误类型、超长参数 | 稳定拒绝，无500、Secret、SQL/内部堆栈 | API/工具响应自动采集；人工核对敏感字段 |
| T8-05 | Markdown/HTML/危险链接/图片事件注入，检查长代码和表格 | 无脚本执行，无危险 DOM，链接和布局可用 | 人工浏览器判断并截图；可复用 Markdown 自动脚本 |
| T8-06 | 缺失认证、错误 tenant/owner、伪造 manager path/mount、直接内部端点 | 401/403/404 或稳定工具拒绝；不创建额外 Runtime | 自动采集容器/挂载前后；人工确认未泄漏 |
| T8-07 | 在隔离环境中制造依赖未知结果或审计持久化不可用；恢复依赖后重试 | fail closed，无伪造成功/永久 pending，无未经记录的企业执行 | 人工选故障；保留日志、operation/trace与恢复结果；禁止改schema |
| T8-08 | 扫描响应、前端错误、下载、服务日志和测试证据 | 无真实 Key/Token/密码/连接串/跨项目字段 | 自动模式扫描+人工审阅；只有命中位置，不复制 Secret |

恢复失败依赖、还原权限并验证账号矩阵后才能继续。不得为了故障注入更改 DSH Core、共享库或远端。

## T9：重复性和短时稳定

独立执行并记录计数，不能以开发者三轮 T5 代替：

| ID | 操作及最小次数 | 检查点 |
| --- | --- | --- |
| T9-01 | T2/T3/T4/T5 核心脚本连续 3 轮，新证据目录/唯一 run tag | 每轮全部通过，失败必须解释和修复，不能靠再次运行消失 |
| T9-02 | 两用户同时真实对话至少 6 轮 | 输出、事件、历史、Runtime Owner 不串线 |
| T9-03 | 登录/退出/切换至少 20 次 | 同浏览器切换与独立上下文均覆盖，无残留本人/他人缓存串用 |
| T9-04 | 权限撤销/恢复至少 3 循环 | API、UI、MCP立即生效；最终恢复原角色/成员语义 |
| T9-05 | 每个只读工具至少 3 次 | 至少覆盖六项主读取，并对两个附加读取同样计数；真实 trace/audit |
| T9-06 | 运行前后及期间采集 restart count、日志、Session/Assignment、容器/卷数和磁盘大小 | 无新重启循环、Owner错配、无限租期、永久运行或失控增长 |

自动复跑可以使用三次 `candidate.ps1 verify -Candidate ...`，每次都会新建证据且含三轮 T5；额外按独立计数补齐20次登录/切换和资源增长观察。也可按矩阵中的底层脚本分别跑核心批次。真实模型调用会产生费用。

## T10：独立最终验收

1. 干净浏览器从18091/18092公开入口开始，随机选择两个账号登录与切换。
2. 比较任务、能力、项目差异，对照账号表的预期。
3. 执行至少两个真实 MCP 读取和一个未授权调用，核对 trace/ledger。
4. 同时发起两个真实对话，检查上下文和归属。
5. 在其中一轮真实生成期间撤销身份；确认结果不交付，后续读取与执行拒绝；恢复测试账号状态。
6. 重启一个 API 和一个明确命名的用户 Runtime，保留原卷。
7. 检查本人历史、项目权限与新生成恢复；打开原任务/Draft。
8. 随机执行三个直接 ID/负向请求。
9. 检查控制台、审计、日志、数据摘要及390宽度的主操作/输入区；核对所有临时权限已恢复。
10. 独立填写结论、执行者、候选指纹、证据、缺陷和 Owner 决策。

真实运行是否发生可由自动证据辅助；回答合理性、泄漏内容、可理解的错误、界面遮挡、恢复体验和已知限制是否可接受必须由测试者人工判断。

独立最终结论使用原计划 `PASS` / `CONDITIONAL PASS` / `FAIL`。仅剩经 Owner 明确接受的 P2 才允许 CONDITIONAL PASS；P0/P1、缺失关键证据或不可重复一律 FAIL。开发者的 `READY_FOR_INDEPENDENT_ACCEPTANCE` 不等于此处 PASS。
