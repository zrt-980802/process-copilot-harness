# 缺陷口径与已知限制

## 严重性和准出

| 级别 | 定义与例子 | 准出要求 |
| --- | --- | --- |
| P0 | 跨账号/项目内容泄漏、Owner串用、Secret泄漏、未授权企业写、历史数据损坏 | 立即停止后续测试，界定影响，修复并全面回归；未关闭不得通过 |
| P1 | 主工作流不可用、撤权不生效、重复模型执行、重启不可恢复、必需证据缺失或结果不可重复 | 阻断最小交付；修复后复跑相关族及T1，重新冻结候选 |
| P2 | 主流程可完成但有明确可复现的非阻断体验/边界问题 | Owner记录接受范围、复现和后续责任；独立验收最多CONDITIONAL PASS |
| P3 | 不影响执行和数据安全的文字、轻微视觉问题 | 记录排期；不能借此降级主流程故障 |

不确定影响时先按较高等级记录。开发者入口出现自动步骤失败默认登记 P1 开放阻断，人工分析后可标明是产品、环境或测试脚本问题；不得仅因重跑通过关闭。

## 每个失败的必填字段

使用 `deploy/dev09-defect-template.json`。记录 case ID、候选和运行目录、账号（不含密码）、项目/workspace、精确步骤、期望、实际、日志/截图/trace位置、时间、影响范围、根因、修复文件、回归测试、复测证据及关闭人。没有用户授权时 fix_commit 必须为空。

状态：OPEN → ANALYZED → FIXED_PENDING_RETEST → FIXED_VERIFIED；独立测试者记录 VERIFIED_CLOSED。开发者修复自测不能填独立关闭人。权限/数据未恢复、未执行必要复测或缺少日志均不得关闭。

本轮最终开发者输出仅为 `READY_FOR_INDEPENDENT_ACCEPTANCE` 或 `NOT_READY`。任何开放 P0/P1、未执行的T0-T7必需项、源码/镜像漂移或业务数据意外变化都必须 NOT_READY 并列出阻断。T8-T10待独立执行是候选交接的正常状态，不得写独立PASS。

## 已知限制与未实现能力

- 本机固定路径和现有数据卷依赖；不是跨机器全新安装器，不包含数据库备份或时间点恢复。
- EE只启动本次需要的认证/账号/权限/MCP部分；不等于完整EE前端/飞书系统部署。
- 主范围为读取、个人/项目对话和原任务回归；受控评审Catalog存在不代表本轮企业写发布已验收。
- 模型请求真实且非确定性，依赖外部可用性；运行耗时和费用随响应变化。
- 有限过期Assignment历史记录保留，不能用其行数判断活动会话；准入检查有限租期，最终检查运行/撤销会话为零。
- request_id重复请求返回明确409，不回放缓存模型结果；旧客户端不传request_id只能获得活动轮次互斥。
- 内部资源 foreign/missing均404；公开通用资源路径由nginx统一403。必须比较同一层，不能误报为不同资源泄漏。
- 权限撤销/恢复会增加revision和审计；原Draft预览会追加下载审计。这些预期变化保留，不覆盖原业务内容。
- 测试会新增标识明确的任务/消息/Operation和停用账号，不清除历史以维持总数。
- 本轮不实施统一Workspace、记忆、数字代理、DSH Core/schema改造、远程部署、容量或灾备认证。

历史已修复5项缺陷见旧运行 `defects.json`，只作为回归依据，不直接写成独立验收关闭。
